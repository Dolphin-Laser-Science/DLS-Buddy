# Code Map

A tour of the codebase for anyone reading, modifying, or forking DLS Buddy. It
describes the directory structure, what each Python module does, and how the
modules depend on one another. For *how to use* the program see the Quickstart and the
User-Manual (`docs/`); for the science see the Theory-and-Equations-Guide (`docs/`); for
where each literature source is used see the Citation Index (`docs/`).

## The big picture

The code is layered. Each row lists the packages of this code base that one package imports
(the `gui` row leaves out a short list of named exceptions, given under **`gui`** below):

```
gui ─────────► app (the controller), plotting, core
app ─────────► analysis, exporting, physics, parsers, core
exporting ───► analysis, physics, core
plotting ────► analysis, physics, core
analysis ────► physics, core
physics ─────► core
parsers ─────► core
core ────────► (no other package)
```

Every dependency points down the list.

- **`core`** defines the common internal data model. Everything else is built on it.
- **`parsers`** turn instrument files into `core` objects. Adding a new instrument
  is one new parser file; nothing downstream changes.
- **`analysis`** consumes `core` objects and returns result objects. Pure functions:
  no GUI, no file I/O, no plotting, no input mutation. Leans on **`physics`** for
  every physically-meaningful number.
- **`app/controller`** is the framework-agnostic brain between the GUI and the
  engine. It owns the workspace, mediates parameter commits, runs analyses, and
  handles sessions. No Qt imports — so the GUI framework could be swapped by
  rewriting only `gui/`.
- **`gui`** is PySide6 widgets only. Widgets call controller methods and draw through
  **`plotting`**; they contain no analysis or physics. The exceptions are imports of engine
  constants and labels, the two generic parsers whose units prompts the load dialogs own, the
  solvent library, and two `exporting` helpers (the suggested-file-name scheme and the CONTIN
  α-selection wording).
- **`exporting`** writes result objects to Origin-compatible CSV, and the synthetic
  generator's artifacts to loadable instrument files.

Two architectural rules worth knowing before you change anything: (1) analysis
functions stay pure, and (2) all analysis/GUI code operates only on the `core`
data model, never on a vendor file format.

## Directory structure

```
<repo root>/
├── README.md              # front door
├── PATCH_NOTES.md         # per-release changes + known issues
├── CLAUDE.md              # contributor/agent orientation + invariants
├── requirements.txt       # pinned dependencies (Python 3.13 venv)
├── test-data/             # tracked datasets (Brookhaven, Malvern, ALV [per-sample subfolders], Synthetic *)
│                          #   Brookhaven/DLS-SLS-Pairs/ holds one folder per sample, each
│                          #   with a paired DLS angular series and an SLS scan; the roster and
│                          #   its conditions are in that folder's parameters.txt
├── docs/                  # committed user-facing docs:
│                          #   1. Quickstart-Guide.pdf, 2. User-Manual.pdf,
│                          #   3. Theory-and-Equations-Guide.pdf, 4. Code-Map.md (this file),
│                          #   5. Citation-Index.md (each source -> where it is used)
├── core/                  # data model + workspace
├── parsers/               # instrument-specific + generic file parsers
├── physics/               # constants and physical formulas
├── analysis/              # pure analysis engines (DLS, SLS, DPLS, utilities)
├── exporting/             # CSV export and the synthetic generator's file writers
├── plotting/              # matplotlib layer
├── app/                   # controller + settings + version (framework-agnostic)
└── gui/                   # PySide6 widgets
```

The tracked files above are everything needed to run, read, and build the program.

## Modules

### `core/` — the data model (start here)
- **`data_models.py`** — the shared internal structures. The most important file in
  the project: every parser produces these objects and every analysis function
  consumes them (`SampleKey`, `DLSMeasurement`, `SLSMeasurement`, the identity
  comparison forms, and the combination doctrine every grouping consumer points at).
- **`workspace.py`** — the framework-agnostic state the controller manages and the
  GUI displays: loaded measurements/traces, samples, grouping (stored results follow
  a regrouped sample to its successor), `SampleResult`, and session JSON. Plain
  Python (no Qt, no matplotlib) so it is headless-testable. Count-rate traces live
  here in one store, optionally back-referencing the DLS measurement they were
  recorded beside; removing a measurement deletes the traces attached to it.
- **`naming.py`** — the one builder for every place a measurement or a sample is
  named: on screen, in a legend, in a hover card and in an export file name. Pure
  string functions over the data model (no Qt, no lookups), so the sidebar, the
  analysis tabs, the controller and the export layer cannot drift apart about what
  a run is called. One rule: the label if set, else the source file stem, with the
  within-sample axes (angle, concentration, Mw fraction) beside it.
- **`notes.py`** — the notes data model: a note is a code, the result attributes it is
  about and the values its clause prints (`Note`), never a sentence. `render` prints a
  note's clause for the screen or for an export, and `qualifiers` reads what a number is
  (apparent, a statistical ±, an estimator, a weighting) off a result's typed fields.
- **`note_registry.py`** — the notes registry: one row per note code with its kind
  (precondition, record, qualifier), its one-clause wording, its Theory-and-Equations-Guide
  section and the reliability flags it fails. Adding or changing a note is one row here.
- **`units.py`** — the input/display unit boundary. The engine always works in
  canonical/SI units; this converts at the GUI edge (g/mL, K, Pa·s, s, cps).
- **`formatting.py`** — the house display formatters (`format_pm` for a value with its
  `±`, `format_fixed_sig` for one without, and their siblings) and the decimal-place rule
  they share with the solvent autofill, which rounds the library's proposed refractive
  index and viscosity at the place their uncertainty supports. It imports nothing from
  `analysis`.

### `parsers/` — files in, `core` objects out
- **`base_parser.py`** — abstract parser base + the preview dataclasses that carry
  extracted parameters to the user-confirmation step + unit converters. Also the two
  parse exceptions: `ParseError` ("not my format" — the loader tries the next parser) and
  its subclass `MalformedDataError` ("this IS my format, and its data is unusable" — a
  diagnosis meant for the user, which the loader must not swallow).
- **`autodetect.py`** — the single "which parser reads this file?" loop, shared by the
  DLS, SLS and count-rate-trace load routes. Pure Python, no Qt, and it never names a
  parser class: the list is an argument, so adding an instrument stays one new parser file.
  Returns a `Detection` carrying the previews, plus any post-commit-point diagnosis a
  parser made along the way so the loader can show it instead of a bare "could not read".
- **`roster.py`** — the instrument parsers the auto-detection tries, one ordered list per
  data kind (`DLS_PARSERS`, `SLS_PARSERS`, `TRACE_PARSERS`). A new instrument format is
  its parser file plus one entry here; the lenient generic parsers stay out of the lists.
- **`brookhaven_dls.py`** — Brookhaven Particle Explorer correlation `.CSV`
  (`BrookhavenDLSParser`) and count-rate trace `.CSV` (`BrookhavenTraceParser`).
- **`brookhaven_dat.py`** — Brookhaven raw ASCII `.dat` export (`BrookhavenDATParser`),
  a different format from the `.CSV` above: a positional numeric header carrying angle,
  wavelength, temperature, viscosity and refractive index, then raw correlator counts
  that are normalized against one of the two baselines the file supplies.
- **`brookhaven_sls.py`** — Brookhaven intensity-vs-angle `.CSV`, in the instrument's
  two layouts. `BrookhavenSLSParser` reads the concentration series (Zimm/Debye plot),
  one preview per concentration; `BrookhavenSLSScanParser` reads the single angular scan
  (Guinier), returning the sample and, when the run recorded a blank beside it, the
  solvent blank first. The two sniffs are mutually exclusive, so their order in the
  auto-detect list carries no meaning.
- **`alv_asc.py`** — ALV correlator `.ASC`: multi-angle (ALV-7012, `Angle(1..12)`)
  or single-angle (ALV-7004, a bare `Angle` key); a DLS correlogram and a count-rate
  trace per angle. NB lag time is in ms. Each correlogram preview carries its own
  channel's trace, so loading the file as DLS data links the two; it also reads the
  file's own mean count rate and nominal duration as records. The `MeanCR` header
  keys are positional (the k-th describes count-rate column k), not detector-numbered
  — the two instrument families number them differently.
- **`zetasizer_clipboard.py`** — Malvern Zetasizer clipboard correlation text
  (tab-separated, g2-1, microsecond lag); one record column per measurement.
- **`zetasizer_export.py`** — Malvern Zetasizer structured *export* (comma-separated,
  one measurement per row); also pre-fills the parameters the file carries (scattering
  angle, wavelength, refractive index, temperature, viscosity, mean count rate,
  sample/material/dispersant names). The export template is user-configured, so the
  module's `_COLUMNS` table is the whole vocabulary — every column optional, order
  free, matched exactly on the normalised header.
- **`panta_xlsx.py`** — NanoTemper Prometheus Panta `.xlsx` autocorrelation export;
  one DLS measurement per file. The only spreadsheet format, so the sniff is
  structural (zip → spreadsheet package → `ACF` worksheet → header cells) rather
  than a first-line token match. Discards the repeated multi-tau block-boundary
  lags, keeping the finer block's estimate. The file carries no parameters at all.
- **`generic_dls.py` / `generic_sls.py` / `generic_trace.py`** — plain-text
  fallbacks (two-column tables) for any instrument/simulation. Kept OUT of
  auto-detection (they match almost anything); used as the explicit fallback.

### `physics/` — the numbers
- **`constants.py`** — every physically-meaningful constant and formula lives here
  and nowhere else: kB, NA, scattering vector q, Stokes-Einstein, optical constant
  K, and the geometry-aware (VU/VV/VH) toluene Rayleigh ratio. Analysis modules
  call these; they never re-implement them.
- **`solvents.py`** — the solvent-property library: refractive index n(λ,T) and
  viscosity η(T) proposed from a chosen solvent, temperature and wavelength. Every
  value is a transparent, provenance-tagged, freely-overridable *default* — never a
  constant baked into an analysis function.

### `analysis/` — pure engines
- **`dls/`** — DLS correlation-function analysis, split into a package by method
  family (public API re-exported from `dls/__init__.py`, so `from analysis.dls
  import …` is unchanged): `_common.py` (shared helpers), `cumulants.py` (linear +
  Frisken nonlinear), `exponentials.py` (single/double/KWW), `distributions.py`
  (NNLS, CONTIN, lognormal, peaks, Rh↔Gamma axis), `angular.py` (Gamma-q^2,
  concentration extrapolation, the per-point fit both run, `fit_point` returning a
  `PointFit`, which a caller may run once and hand them, Rh↔Gamma converters),
  `replicate.py` (replicate-correlogram averaging), `modes.py` (mode-resolved
  dynamics: per-run mode extraction for the mode map, `extract_modes` for one run and
  `extract_mode_runs` over a map's runs, each run's outcome a `ModeRunOutcome`
  with its points tagged by run; per-family Gamma-q^2 fits with the
  q^2+q^4 deviation form, fast/slow amplitude-vs-q report).
- **`sls.py`** — SLS: Mw, Rg, A2 from angle/concentration intensity; unified
  calibration, Debye, Zimm/Berry, Guinier, single-angle, calibration-free A2, and the
  full-angular form-factor P(q) fit, with `rg_values_agree` and `form_factor_consensus_rg`
  (whether a degenerate fit's solutions agree on Rg, and their mean when they do).
- **`form_factor.py`** — single-particle form factors P(q) (sphere, Gaussian/Debye
  coil, ellipsoid, Mie sphere) and the Rg<->R conversions, shared by the SLS
  form-factor fit and the synthetic forward model.
- **`mie.py`** — vendored full-Mie solver for a homogeneous sphere (Bohren & Huffman /
  Wiscombe): scattering coefficients a_n/b_n, amplitude functions S1/S2, efficiencies,
  and the per-particle intensity + form factor the SLS Mie fit and DLS Mie reweighting
  consume. Pure NumPy, no runtime dependency.
- **`optical_model.py`** — the sphere optical model that re-expresses a DLS
  intensity distribution as volume/surface/number-weighted (Rayleigh R^6 / RDG
  V^2 P / full Mie |S1|^2), with the documented `x`/`qR`/`|m-1|` validity gate.
  Report-only (no ±).
- **`depolarization.py`** — static DPLS: depolarization ratio, Cabannes
  isotropic/anisotropic split, optical anisotropy, from paired VV/VH intensities.
  Dynamic DDLS: each paired angle's VV and VH field decay rates, averaged over its
  replicate correlograms' cumulant fits (`assemble_ddls_rate_points`, returning a
  `DDLSRateAssembly`), and D_t and D_r from those rates (`analyze_ddls`).
- **`uncertainty.py`** — the statistical-uncertainty toolkit (HC3 covariance,
  delta-method propagation, replicate mean/SE). Where the rest of the
  engine reports a `±`, it comes from here. It also owns the shared least-squares
  primitives the engine fits through, so that each raising NumPy call and the
  finiteness/conditioning guard sized to it live in one place.
- **`trace_analysis.py`** — intensity-trace signal-analysis diagnostics: trace
  statistics, robust baseline, outlier flagging both globally and against a moving
  window (the windowed Hampel decomposition: rolling baseline, impulse flags and
  disclosed abstentions), baseline normalisation,
  running average, block-variance (SE vs block size, and the Allan deviation off
  the same block means), count-rate histogram with Gaussian/Poisson fits + Fano
  factor, the ADF stationarity test, a Welch power spectral density with its
  equivalent-degrees-of-freedom statement and a shot-noise floor, and the
  periodogram false-alarm test for periodicity.
- **`derived_sls.py`** — turns DLS runs' committed mean count rates into one
  static (SLS) angular series, so a goniometer that recorded only correlograms
  still yields a full static analysis. Averages same-angle runs through the
  shared replicate-identity check and records which runs and which count-rate
  sources produced each point.
- **`mode_partition.py`** — mode-resolved static intensities (the Sedlák
  partition): splits one concentration's excess Rayleigh ratio by the DLS
  modes' per-angle amplitude fractions (each mode's share becomes an ordinary
  Rayleigh result the SLS fitters consume unchanged), and the amplitude-Guinier
  fit of one mode's series for its apparent, mode-resolved size.
- **`utilities.py`** — the remaining cross-cutting helpers: the i*sin(theta) check,
  rho = Rg/Rh, the Rg/Mw/A2 scaling power-law, the provenance-aware result-candidate
  picker, and the synthetic correlogram generator.
- **`synthetic_dataset.py`** — the reusable synthetic-data engine behind the in-app
  Utilities synthetic-data generator (pure forward models and builders; no plotting,
  no file I/O — its writers are `exporting/instrument_files.py`).

### `exporting/` — results out
- **`export.py`** — Origin-compatible CSV writer (Long Name / Units / Comments /
  Parameters header rows) for the DLS and SLS result objects. An export that
  traces to one measurement carries a `Source file` column with that
  measurement's file name; one built from several names its sources in the
  Comments cells instead.
- **`filenames.py`** — the suggested-export-filename scheme, in three rules: one
  measurement (`{polymer}-{solvent}_{analysis}[_{method}]_{name}_{angle}deg`),
  one sample (`{polymer}-{solvent}_{analysis}`), or cross-sample
  (`{analysis}`). Also splits a batch into the stem the save dialog shows and
  the suffix each file appends to whatever the user types. Windows-safe
  sanitization, a length cap and a reserved-device-stem guard throughout. Pure
  strings; the GUI reaches it through `gui/export_helper.py`.
- **`instrument_files.py`** — the synthetic generator's file writers: a built artifact
  from `analysis/synthetic_dataset.py` as a file a real parser loads (ALV `.ASC`, the
  two Brookhaven SLS `.csv` layouts, the Brookhaven raw `.dat`, a count-rate trace, the
  generic parser's two-column correlogram CSV, the VV/VH pair stand-in with its reader),
  and the orchestrators that regenerate the six generator-owned `test-data/Synthetic`
  folders from their fixed recipes and seeds (the other committed synthetic folders are
  regenerated by maintainer scripts).

### `plotting/` — the matplotlib layer
- **`plots.py`** — ax-accepting, handle-returning plot functions with no blocking
  `show()`; built independently of the GUI and designed to drop into it. Owns the
  color palette (`set_palette`).

### `app/` — the framework-agnostic brain
- **`controller.py`** — the layer between the GUI and the engine: owns the
  `Workspace`, mediates parameter edits (commit/working state), orchestrates
  analysis runs, and reads/writes sessions. It holds the `Controller` class and the
  module-level helpers its methods use (the DLS parameter specs, the Cross-Sample
  candidates' labels and source ids), and imports the typed state, the fit requirements,
  the note helpers and the result store from the modules listed after it. No Qt.
- **`calibration.py`** — the SLS calibration (`CalibrationState`), the session's and
  any sample's own: the calibrant point, the standard and its refractive index, and the
  calibration constant k_c computed from them. No Qt.
- **`sample_state.py`** — the per-sample choices the controller keeps beside the
  workspace: the SLS data mask and the Mode Map's picked mode families and recorded mode
  sets; and the plan a removal's confirm is built from when the removal would change a
  series' blank. No Qt.
- **`fit_requirements.py`** — what each SLS and DLS analysis needs before it can run,
  declared once (`SLS_FIT_REQUIREMENTS`, `DLS_FIT_REQUIREMENTS`): the tabs gray an
  analysis from it, and the User Manual's requirements tables are generated from it. No Qt.
- **`cross_sample.py`** — the data the Cross-Sample tab shows: a sample's rho = Rg/Rh with
  its sources, the scaling plots' points and power-law fits, and the branching readout.
  No Qt.
- **`session_json.py`** — how a session file stores a NaN or infinite value so the file
  stays strict JSON, and how it reads the value back. No Qt.
- **`result_notes.py`** — the notes behind a result's labels and Summary rows: the scale
  clauses of an Mw or A2 label, the precondition notes behind a flagged value and the
  label suffix they make, the notes a pooled or averaged result relays from its sources,
  and a Summary row's flag text. No Qt.
- **`result_store.py`** — the one owner of the controller's stored analysis results, the
  run stamps their freshness is judged by, the Cross-Sample candidate memos, and what the
  DLS sub-tabs draw of a run: the signature each tab ran it under, a run a Settings clear
  superseded while its tab keeps drawing it, and a refused run's failure line
  (`ResultStore`): every removal of a result takes its stamps with it, and a removed
  sample's entries go with the sample. No Qt.
- **`loading.py`** — the file loader: auto-detects each file over the parser roster,
  falls back to the kind's generic parser, and hands each preview to the controller in one
  fixed order (the raw arrays and parameters, the vendor records, the file's own trace, the
  count-rate seed). The widgets keep the file dialog and the reports, and pass the generic
  fallbacks' units prompts in as callbacks. No Qt.
- **`synthetic.py`** — the Synthetic Generator's recipe: which builder each artifact
  kind calls with which inputs (`SynthRequest`, filled from the Utilities tab's fields),
  how a ticked artifact is saved, and in which order the single-sample injection adds
  built artifacts to the workspace.
  The physics and file formats it reaches through the controller. No Qt.
- **`analysis_region.py`** — the one reading of the DLS analysis region (the delay
  window and baseline span set on the Correlogram sub-tab) as one fit's engine inputs:
  only a part the user moved is applied, and a span is read only inside the window.
  Every surface and background path that fits under the region calls it. No Qt.
- **`settings.py`** — global user preferences as a dataclass (`SettingsState`).
  Rule: settings *seed* a module's controls, never silently override a per-run value.
- **`version.py`** — the single source of truth for `__version__` (shown in the GUI
  window title and the generated guide PDFs).

### `gui/` — PySide6 widgets over the controller, `plotting` and `core`
- **`main.py`** — entry point (`python -m gui.main`): sets the Qt/matplotlib
  backend and runs the event loop.
- **`main_window.py`** — the shell: sidebar navigator + the six module tabs over one
  shared controller; owns the load dialogs and their reports, the load itself being
  `app/loading.py`'s.
- **`data_module.py`** — Data tab: the parse -> confirm -> commit parameter step
  (the only tab that edits parameters).
- **`field_labels.py`** — the single source of truth mapping internal data-model
  field names to their user-facing labels, plus a translator that swaps the former
  for the latter inside user-visible messages, and the one test of whether a ± is
  shown beside a value. Physics-free; standard library only.
- **`dls/`** — DLS tab: analysis-only sub-tabs over committed parameters, with
  multi-measurement co-plotting, split into a package by sub-tab: `module.py`
  (`DLSModule`, the tab), `correlogram.py`, `distribution.py`, `sample_analysis.py`
  (Gamma vs q^2 and D vs c), `mode_map.py`, `ddls.py` and `summary.py` (one sub-tab
  each), `averaging.py` (the replicate-averaging dialog), and what the sub-tabs share:
  `region.py` (the analysis region and its checkbox), `fits.py` (fit methods, labels,
  residual panel), `legend.py` (plot keys), `tables.py` (result tables), `common.py`
  (stale hints, weighting titles, picker help) and `bases.py` (the sub-tab bases).
- **`dls_module.py`** — re-exports every name of `gui/dls/` under one import path.
- **`sls/`** — SLS tab: per-sample static-scattering analysis (calibration panel +
  Zimm/Berry/Debye/Guinier/... + data masking), split into a package by sub-tab:
  `module.py` (`SLSModule`, the tab), `analysis_tab.py`, `derived_intensity.py` and
  `mode_resolved.py` (one sub-tab each), `rows.py` (the result-table rows) and
  `common.py` (what the sub-tabs share).
- **`sls_module.py`** — re-exports every name of `gui/sls/` under one import path.
- **`cross_module.py`** — Cross-Sample tab: the aggregate-scope module (rho = Rg/Rh
  table + Rg-Mw / A2-Mw scaling) with provenance-aware source pickers.
- **`utilities_module.py`** — Utilities tab: trace diagnostics, the i*sin(theta)
  check, and the synthetic-data generator's panel, preview and readout (its recipe is
  `app/synthetic.py`'s).
- **`solvent_explorer_module.py`** — a Utilities sub-tab: a display-only calculator
  over the solvent-property library (`physics/solvents.py`), for looking up n and η
  at a chosen solvent/temperature/wavelength without touching an analysis.
- **`settings_module.py`** — Settings tab: edits and persists `SettingsState`.
- **`distribution_fit_fields.py`** — the distribution-fit controls the Settings tab
  and the DLS Distribution and Mode Map sub-tabs share (`DistributionFitFields`).
- **`plot_controls.py`** — reusable per-axis scale/min/max/autoscale widget placed
  next to a plot.
- **`export_helper.py`** — tiny shared helper behind the tabs' "Export CSV..." buttons.
- **`plot_overlays.py`** — shared GUI plot-overlay helpers (grey excluded/masked-point
  markers + legend re-issue) used by the DLS, DDLS and SLS draw paths so they can't
  drift apart by hand. Overlays are GUI-owned, never baked into the saved figures.
- **`worker.py`** — background dispatch for the heavy controller calls: an
  `AnalysisRunner` on a `QThreadPool` runs one analysis job at a time off the UI
  thread, so the controller stays Qt-free and the window never freezes during a fit.
  A `RunSlot` per Run button holds that button's staleness epoch and, where a busy press
  is queued rather than refused, the latest such press's target, retried once the
  worker frees.
- **`help.py`** — the in-program help system: two tiers, a click-through `?`
  `HelpBadge` (how-to-use) and passive `setToolTip` hover text (calculation nuance),
  wired in by `section_header` / `add_help_to_groupbox`.
- **`note_text.py`** — the remedy table: what to do about each note code, shown when the
  user clicks a note. Plain data, no Qt; the clause itself lives in `core/note_registry.py`.
- **`notes_block.py`** — the notes block a result surface shows under its values: one
  line per distinct precondition, its marker at each value the note is about, the remedy
  on click; and the qualifier words a row or column label carries.
- **`theme.py`** — the theme-aware colour-token layer (light/dark) every widget reads,
  so a colour is named once and never hard-coded per tab.
- **`widgets.py`** — small cross-module Qt widget helpers (e.g. the `RoomyTabBar`
  tab-bar spacing fix, the section-header idiom for grouped dropdowns, and
  `make_plot_pane`, an embedded plot's figure, canvas, toolbar and axis bar) shared by
  more than one tab.
- **`solvent_picker.py`** — the one way the solvent library is offered in a dropdown,
  used by the Data tab, the Solvent Explorer and Settings so all three show the same
  roster the same way: every library solvent, split into measured/estimated sections,
  with the canonical name on `itemData`.

A comprehensive `pytest` validation suite backs every engine and GUI surface described
above; it lives in the maintainer repository and is stripped from the public release, so
a forked clone builds and runs without it.
